# تقرير تجربة دورة الحياة — منصة حُلّل

**التاريخ:** 2026-09-04  
**البيئة:** محلية (`http://127.0.0.1:8000`) بعد `migrate --seed`  
**المستخدم:** Super Admin — `0500000000`  
**المنهج:** زحف HTTP موثّق الجلسة + فحص HTML/السياسات + جولات واجهة يدوية (متصفح) على دورات الحياة

---

## الخلاصة التنفيذية

المنصة **غنية بالوحدات ومساراتها موجودة في الغالب**، والبيانات التجريبية تسمح بفتح أغلب الشاشات. لكن دورة الحياة «من أولها لآخرها» **غير مكتملة تشغيلياً** في عدة محاور:

1. أعطال صلاحيات/تحميل علاقات تمنع المعاينة والتنزيل رغم ظهور السجل.
2. وحدات مالية وموارد بشرية بلا بيانات كافية لمسار كامل (إنشاء → اعتماد → إقفال).
3. مسار تعديل المحضر مبني في الواجهة لكن **غير مُزرع وغير مُمارَس** في البيانات.
4. تضارب بيانات داخل المحضر (مسؤول غير حاضر / جدول أعمال فارغ).
5. عناوين تبويب المتصفح ثابتة على «الرئيسية» في صفحات كثيرة — يضعف التوجه والإبلاغ عن الأخطاء.

**الحكم العام:** صالح لاستكشاف الوظائف، **غير جاهز لاعتماد تشغيلي** قبل إصلاح الحرج والعالي أدناه وإكمال جولة حياة واحدة ناجحة لكل تبويب من الـ 11.

## ما يعمل بشكل مقبول

| المجال | ملاحظة |
|--------|--------|
| تسجيل الدخول (بعد ضبط الهاتف/`must_change_password`) | مسار POST سليم؛ الوصول للوحة |
| الرئيسية | مؤشرات وملخصات تظهر |
| الفريق / المهام / الاجتماعات / المستندات (قوائم) | صفحات تُحمَّل وفيها Livewire وأزرار مربوطة |
| أرشيف المحاضر | نصوص المسار الرباعي ظاهرة؛ زر «طلب تعديل» مربوط |
| المالية (شاشات) | معظم المسارات تُرجع 200 مع عناوين صحيحة |
| الشراكات / المشاريع / الهيكل / الصلاحيات | الصفحات تفتح ومكوّنات Livewire موجودة |

## المشاكل المؤكدة (واجهة أو بيانات/تدفق)

### حرج

| # | المسار | الأداة | المشكلة | إعادة الظهور |
|---|--------|--------|---------|---------------|
| H1 | `/documents` | مستودع المستندات | مستندات سرية «القسم» تظهر في الجدول لكن **بدون معاينة/تنزيل**، مع بقاء **حذف** أحياناً. السبب الجذري: التحميل المسبق `uploader:id,name` بلا `org_unit_id` فيجعل `DocumentPolicy::canAccessDepartment` يفشل في الواجهة بينما Gate على نموذج كامل ينجح. | افتح المستندات → صفوف السرية «القسم» (مثل التقرير المالي / محضر الجمعية / سياسات) → أيقونات العين والتنزيل غائبة |
| H2 | `/documents` + السياسة | صلاحية الحذف | يمكن ظهور زر حذف لمستند **لا يُسمح بعرضه/تنزيله** (`delete` يعتمد `documents.create` دون نفس قيد السرية) | مستندات قسم خارج جذر وحدة المستخدم: حذف ظاهر، تنزيل غير ظاهر |
| H3 | دخول أول مرة | تغيير كلمة المرور | في بيئة البذرة كان `phone` فارغاً لدى الأدمن و`must_change_password=true`؛ مسار الإلزام يكسر التجربة إن لم تُضبط الأسرار/البذرة | مستخدم جديد بإلزام كلمة المرور دون بيانات جوال صحيحة |

| A4 | `/expenses` | طلبات الصرف | لا بيانات (`0` سجلات) + رسالة الفراغ مكررة مرتين؛ دورة الاعتماد غير قابلة للتجربة من البذرة | افتح الصرف |

## ملاحظات منهجية (صدقية الاختبار)

- بعض بلاغات «الزر لا يستجيب» من الأتمتة البصرية **قد تكون إخفاقاً في إصابة هدف Livewire**؛ حيث وُجد `wire:click` في HTML لأزرار الإجازات/الصرف/الحضور/الهيكل. **المشاكل المدرجة كحرج/عالي أعلاه مؤكدة من HTML أو Gate أو عدّاد البيانات.**
- تسجيل الدخول عبر تعبئة الحقول آلياً كان متذبذباً؛ الاعتماد التشغيلي للزحف كان على جلسة CURL بعد POST ناجح.

## أولويات الإصلاح المقترحة

1. **فوراً:** في `DocumentsIndex` تحميل `uploader:id,name,org_unit_id` (أو إزالة تقييد الأعمدة) ومواءمة `delete` مع `view/download`.
2. **عاجل:** تصحيح `title`/`layouts.app` لكل صفحة Livewire.
3. **عاجل:** بذرة كاملة لمسار واحد على الأقل: صرف، تقييم ربعي، تعديل محضر (طلب→موافقة→تعديل بند→اعتماد+نسخة).
4. **مهم:** ربط جدول الأعمال ببنود المحضر والتحقق من أن المسؤول ∈ الحضور.
5. **مهم:** تعريب رسائل التحقق في `/login` وضمان أن البذرة تضع `phone` + سياسة كلمة المرور الأولى بشكل صريح.
